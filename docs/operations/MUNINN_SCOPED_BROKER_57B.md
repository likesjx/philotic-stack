# Narrow synthetic Muninn connection on installed 57b

This branch backports the reviewed fixed credential listener, exact-record vault
ACL resolution, named supervisor FD adoption, guest FD isolation and bounded
shutdown to installed source `57b13ba0087722a2de062ff86710ae64a510d445`.
Activation defaults off. General IPC, guest manager, routing, context, privacy
storage schemas, Philote and model controllers remain on that baseline. No
LifeGraph, semantic deduplication or private recall is enabled. The existing
Muninn backend supports the gateway's authenticated unary JSON POST `/mcp`;
the backend needs no broad hotel upgrade for this profile.

The new resolver additionally requires exact stored secret reference/kind and
scope `percival_connection_test` before decrypting the same ACL-checked snapshot.
Only the two fixed operations for Muninn observe and issuer introspection exist.
This metadata pin does not prove a native key's actual vault/mode: that must pass
synthetic-only installed acceptance before exposing the route.

Gateway/issuer snapshots are pinned in
`services/personal-mcp/issuer-fixture/source-pins.json` for interoperability tests.
The copied issuer fixture is not a deployable issuer or new canonical owner.
The real identity dependency and separate client policy must be merged/deployed
by their owners. Actual dot/Claude callback URLs and transport support remain
owner facts; `.example` callbacks are synthetic fixtures only.

## One exact approval transaction

This is source preparation, not authority to perform any following action.
Use the successful exact-head CI package receipt for one `bin/aiua` candidate;
do not install a develop hotel-trio or the separate Beacon controller package.

1. Under the existing release and historical-worker fences, confirm current
   canonical `/opt/philotic/bin/aiua`, installed/running hashes and supervised
   ExecStart; preserve the exact baseline preimage and existing unit/drop-in
   hashes in the operator's protected rollback location. Preserve Philote,
   heal, controller hashes, model ladder and all existing drop-ins. Current
   root-controlled ancestry/fence proof remains required for replacing this
   binary; no unrelated-process zero-count condition is required.
2. Approve a separately selected free UID/GID for `percival-gateway` (991 is
   occupied), distinct from the actual hotel UID. Review the three source
   templates under `services/personal-mcp/deploy` against actual installed
   secret/database/general-IPC paths. Supply the effective inaccessible paths
   through the existing deployment role; do not make hotel paths world-readable
   or grant the gateway the general hotel socket.
3. Through the approved encrypted Philote operator path, provision only a
   native observe credential pinned to `percival_connection_test` and a separate
   random introspection credential. Both stored records must use exact singleton
   role `percival-personal-recall`, guest `percival-personal-gateway` and synthetic
   scope. Give the issuer only the existing verifier representation. No raw key
   goes into argv, environment, Ansible values, gateway JSON, logs or files.
   This source does not provision either credential or any grant.
4. Review the two actual callback allowlists, resource/audience, issuer image,
   subject and independent client grants. Configure the existing gateway with
   only `muninn_recall`, `memory:recall`, per-client policies and the synthetic
   vault. Use the fixed broker socket for both credentials and the existing
   loopback Muninn unary endpoint. Keep operations authorization separate.
5. Stop the gateway; stop/drain the hotel under its existing supervisor. Save
   and hash the aiua preimage, atomically replace only aiua with the reviewed
   candidate, and install only the additive scoped socket/drop-in, root-owned
   nonsecret policy and reviewed gateway configuration/unit. Reload systemd,
   start the socket then hotel, verify exact running candidate SHA and one
   `percival-scoped-vault` descriptor, and verify no guest inherits that FD.
   Hotel restart interrupts its existing guests; this is not a live/no-restart
   change. Gateway stays stopped until installed identity/FD/isolation checks pass.
6. Start the gateway only after actual namespace denials and synthetic native
   observe-vault pinning/no-learning acceptance pass. Test both clients with
   synthetic packets, exact callbacks/PKCE/resource binding, cross-client
   code/refresh denial, independent revocation and revocation during recall.
   No private records or real provider prompts enter acceptance. Record bounded
   acceptance metadata and hashes; release fences only after verification.

Approval must name the candidate archive/manifest/binary hashes, baseline preimage,
affected services, actual UID/GID, policy/config/template hashes and test bounds.
Missing values are a stop, not permission to invent an identity or broaden access.
Do not repeat the completed aggregate process/unit probe to gather these facts.

## Rollback of this transaction

Retain fences. Stop gateway, stop hotel and scoped socket, remove only the new
scoped drop-in/socket/policy and restore approved gateway unit/config preimages.
Do not use an empty `Sockets=` assignment to undo the additive association.
Restore the aiua preimage by its pinned hash, reload systemd, restart baseline
hotel and verify running original hash plus preserved guest registrations and
model ladder. Keep gateway in its original discovery-only state. The socket
descriptor and all new handlers must be closed before gateway access resumes.

No schema migration is introduced. Restoring aiua does not delete provisioned
credentials/admissions: their independent disable/revocation belongs to the
explicit approved credential/grant rollback action, not a silent database restore.
If original runtime/registration or rollback cannot be proven, retain fences.
