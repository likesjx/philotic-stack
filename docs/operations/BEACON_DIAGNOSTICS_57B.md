# Selective diagnostics candidate on installed source

Base: `57b13ba0087722a2de062ff86710ae64a510d445`. This branch is an installed-baseline candidate, not a replacement for develop and not permission to deploy. Its draft targets a dedicated baseline reference so reviewers can inspect the selective change without proposing to revert newer develop work.

Production changes add content-free, bounded attempt start/finish observations around the existing ordinary controller retry loop. Provider invocation, input, output, retry/rotation budgets, fallback, context, model selection, hotel/Philote and reply paths stay at the baseline. Requested model is only the explicit task model; an omitted default is unknown. Route phase/reason remain unknown because the installed old Philote does not produce that metadata. These records do not prove HTTP receipt or final user delivery, and native-live, decisions and auxiliary pin paths are outside this observation change.

The observation modules are selected from merged diagnostics source `8e21074`. They retain the 128-record/900-second lazy-expiry buffer, 64-events-per-minute limiter, nonblocking lock/drop behavior, fixed category labels and hashed identifiers. No prompt, reply, raw error or model identifier is emitted. Existing external journal retention remains an operator fact.

Synthetic acceptance uses the baseline hotel's real IPC server and the production controller loop. Distinct OpenRouter, Gemini and Ollama mock providers receive batch success, failure and streaming tasks; acceptance checks untouched parsed provider input, actual returned success/failure envelopes, streaming token forwarding and real diagnostic events. Providers are synthetic and never make an HTTP request. The child process clears ambient environment and owns disposable trace storage and an in-memory hotel graph. This does not prove real provider registration, provider/model support, installed binaries, systemd isolation, or production readiness.

No local Rust compiler is installed. Hosted source-only CI uses the repository's existing Rust version/tooling, synthetic public vault fixture, read-only repository permissions and no deployment or private credential reference. No production runtime action is performed. A formatting patch is an explicit review artifact; the final gate requires no formatting diff.

Before proposing deployment, the operator must identify actual registered controller guests and hashes, affected agents and journal audience/retention. The release owner must provide a supported guest-component bundle, installed-state preconditions, shared fencing, historical-worker terminal evidence and consistent rollback. The existing retired hotel-trio release cannot deploy this candidate. The parent coordinates any later concrete rollout approval.
