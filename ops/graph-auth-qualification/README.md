# Synthetic Memgraph safe-link restore — test only

This candidate adapts the passing graph entry inventory fixture at commit 7a1bb261726554a92cde1b437b523184c02efb7a. In an exclusive fresh Linux runner it uses the same pinned graph image and durability flags, acknowledges one synthetic graph write, verifies it after a graceful restart, stops and verifies the owned graph, then copies its complete data tree to a distinct fixture-owned directory. It preserves without following only links directly under `databases/memgraph` whose text is exactly `../../` plus the same basename; excluded and hidden names, all other links and special entries are refused. This matches the bounded compatibility-link shape in the pinned v3.10.1 source, but is not a general-purpose backup or an adversarial custody mechanism. Source, target and before/after inventories compare regular-file hashes, modes, sizes and exact link text, with limits. A second network-none graph container starts from the copy, verifies authentication, denial controls and the synthetic record; both exact owned containers and scratch are checked during cleanup.

The copy assumes an exclusively owned fixture root with no concurrent or hostile writer after confirmed shutdown. Leaf hashing uses no-follow opens but ancestor traversal and `copytree` do not establish race-proof host custody; no crash/power-loss durability, external storage, full-stack backup, revocation reconciliation or production recovery is proved. Unknown links, incomplete copy, uncertain create/reap, wrong mount or unknown cleanup fail closed. The fixture does not print names, link targets, credentials or payloads. The local environment denied a prior Unix socket bind; socket classification is tested with fake metadata and that operation was not retried. No production data, keys, services, credentials or deployment are used.
