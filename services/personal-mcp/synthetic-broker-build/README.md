# Synthetic broker per-process protection candidate

Local successor to the published draft build candidate. No publication, Linux execution or production activation of this revision is authorized yet. The global-sysctl workflow candidate is held and excluded here.

The supervisor remains root and retains the operator key pipe. Its mount-namespace child inherits only a private socket endpoint, never that pipe. The private noswap tmpfs is empty of key data during startup. Root remains through final exec. Rust accepts existing fs.suid_dumpable 0 or2, rejects1, clears groups and capabilities and irreversibly drops all UID/GID identities. It checks actual transition dumpability0/2, explicitly sets and verifies dumpability0 again, and validates identities/capabilities/no-new-privileges. No subsequent exec or credential transition occurs.

Only then does Rust send READY on the private socket. Root reads the operator pipe after this exact bounded handshake and sends the canonical key line. The protected helper creates the mode0400 key file for the existing vault loader. Neither key arguments nor environment values are used. Keychain remains disabled. The socket/key reads have deadlines and wrapper cleanup retains its child-process deadline. No sysctl write exists.

During the UID transition, Linux ptrace permission logic denies dumpability2 as well as0 to peers without CAP_SYS_PTRACE. Root identity before transition, and the kernel credentials/dumpability ordering, prevent a same-UID attacker preopening proc handles. Delaying delivery also keeps the key absent from child memory, inherited FDs and tmpfs during that interval. Host root/CAP_SYS_PTRACE and policy administration remain trusted. Same-UID signals can cause denial of service. Noswap protects the tmpfs file, not Python/Rust heap copies; this does not claim process-memory swap prevention.

The Linux fixture requires existing fs.suid_dumpable=2 and never changes it. A shared-bootstrap callback reports actual UID999/dumpability2 then SIGSTOPs before the final prctl. The root harness verifies the stop, performs same-UID proc root/fd/mem and ptrace probes, verifies the original dummy key pipe remains unread, and resumes with SIGCONT. It then probes the protected key-bearing state, normal/timeout cleanup, ownership and actual noswap mount. Ordinary same-UID positive controls remain mandatory. A passing receipt includes transition denial and delayed delivery evidence, plus exact source/binary hashes.

CI uses the existing disposable GitHub-hosted Ubuntu workflow, pinned actions/toolchain and locked downloads followed by offline tests/build. It may create a temporary nonlogin UID999 account and private dummy mounts/files. No real credentials or production configuration are fixture inputs. No tests are weakened if policy2, noswap or required privileges are unavailable: acceptance fails. Binary/receipt publication remains success-only, seven-day retention; source/logs are public after approved publication. No merge/deployment is included.

Linux runtime tests have not executed for this revision. macOS tests do not compile the Linux-only bootstrap branches. A successful build and adversarial run under unchanged2 are required before any real-key handoff. Production metadata alone does not prove mount permissions or runtime isolation.
