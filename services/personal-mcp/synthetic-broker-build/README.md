# Synthetic broker build and public isolation fixtures

This is an unpublished build-only candidate for the existing public repository. No production identities, real keys, server addresses or private deployment configuration are fixture inputs. Unused inherited device inventories, external dependency tests and internal documentation have been removed. Remaining inherited device/person/address examples are generic fixture values. The crypto and vault storage APIs remain unchanged; the helper now adds a root-to-runtime privilege transition before credential creation.

No production secrets, SSH, private checkout, OIDC, deployment or package installation is configured.

The GitHub-hosted ubuntu-24.04 runner is mutable; compiler, libc and linker metadata are retained. Tests/build run offline after the locked fetch. A public root fixture then runs on the disposable runner. It may create a temporary non-login UID999 system account with no home/password, a fixed fake-helper installation used only for the fixture, private tmpfs mounts and public temporary files. It cleans these after the run. These are CI-only effects, not production access. The seven-day artifact contains the helper, hashes, compiler/source provenance and acceptance receipt, and follows public repository artifact-access rules. Source and job logs are public.

## Implemented private startup correction

The prior design dropped to UID999 in Python and then executed a normal helper, resetting dumpability and allowing potential same-UID /proc traversal. The corrected wrapper stays UID0 through its final exec. At the start of the Rust helper, private_start.rs requires Linux fs.suid_dumpable=0, disables core dumps/dumpability, clears keepcaps and ambient capabilities, enables no-new-privileges, clears supplementary groups, and irreversibly drops real/effective/saved GID/UID to the runtime account. It verifies all identity values, dumpability0, no-new-privileges and empty inheritable/permitted/effective/ambient capabilities. No exec occurs after that drop. Ordinary UID999 mode cannot create secrets; it may perform key-free deletion.

Root key input remains an operator-supplied private pipe. No discovery mechanism exists. The wrapper's private noswap tmpfs contains a mode0400 key file under a temporary HOME for the existing vault loader; no persistent root-key file or environment value is configured. Root processes hold the key before the transition, and the nondumpable UID999 process uses it afterward. Keychain remains disabled. Host root/CAP_SYS_PTRACE are trusted; same-UID denial-of-service signals remain possible and do not grant key access. The existing two hotel adoption/restoration restarts are unchanged and are not executed here.

Reference semantics: https://man7.org/linux/man-pages/man2/execve.2.html and https://man7.org/linux/man-pages/man2/pr_set_dumpable.2const.html . No setuid bit, file capability or sysctl mutation is used. Eventual Linux verification requires root with mount-namespace, setuid/setgid and privilege-control capabilities, tmpfs noswap support, and an existing fs.suid_dumpable=0 policy. If the runner has another value, refuse; do not change it automatically.

## Adversarial evidence and gates

The Linux fixture compiles a Rust example sharing the exact production bootstrap module. A same-UID sibling positive control must successfully read another normal process's /proc/root and /proc/fd paths. The sibling then probes root/fd/mem/ptrace access against the protected bootstrap process. Denials count only with EPERM/EACCES while the target exists before and after; missing/dead targets cannot pass. Memory/ptrace positive-control restrictions from Yama are reported separately, not called bootstrap evidence. The fixture also verifies private host-path hiding, mode0400, UID999, noswap and normal/timeout cleanup using only the public dummy key.

Acceptance binds four hashes: adapter, bootstrap source, released helper binary and main source. The private local coordinator requires these exact hashes, positive receipt flags and separate action approval before real-key creation. Production coordinator sources/identity/config are not included in this public patch. The receipt is not generated by local preparation or source review; Linux must actually pass. Real-key use remains blocked until that matching receipt and explicit authorization exist.

Independent source review passed the corrected isolation implementation, including permission-error discrimination and executable-hash binding. Native Mac tests do not compile or prove the Linux-specific transition. The Linux build/adversarial fixture has not run. Public input tests and source checks are supporting evidence only.
